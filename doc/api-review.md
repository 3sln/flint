# API review

Every built-in namespace, one section each, so they can be gone through a few
at a time rather than all at once.

**How to use it.** Tick `**Reviewed:**` when the interface and the boundary
look right. If they do not, leave it unticked and write what should change
under **Change requests** — that is the durable form, because an unticked box
says only "not looked at yet" while a recorded request says what is wrong.

Ticking means the NAMES, the ARITIES and the BOUNDARY are right: that this
namespace should exist, that its vars belong in it rather than somewhere else,
and that nothing published here should be private (or vice versa).

`bin/check-api-review` fails when a namespace exists with no section here, so
the list cannot fall behind the code. It does not check the boxes — only the
maintainer ticks those, the same rule `DECISIONS.md` follows.

## Where the boundary already is, and where it is not

**`doc/manifest.edn` is the published surface**, generated by `bin/manifest`
and asserted by `test/manifest.clj` — every var it lists is checked to be
callable from a compiled module. It covers 22 namespaces.

**Fourteen `lib/flint` namespaces are not in it.** That is not a bug, but it
is unreviewed: nothing records whether they are public API, internal machinery
that happens to live in `lib/`, or something in between. They are marked
**UNMANIFESTED** below, and that is the first boundary question for each of
them — several are plainly internal (`flint.nfa` and `flint.pike` are the
regex engine's insides), and several plainly are not (`flint.bytes`,
`flint.table`).

# Served, not linked

Virtual namespaces: a program `:require`s them and the compiler emits a call
over a port (`DECISIONS.md#system-namespaces-and-deps`). The boundary question
here is sharper than for a library, because **this is the whole surface between
a flint program and the world** — anything reachable is reachable through one
of these.

Both the Rust and the JavaScript CLI must serve an identical list;
`bin/check-sys-catalogue` fails on any drift in namespace, var, arity or order.
